# GitHub CMS authentication broker contract

Phase G1 keeps the public control panel static on GitHub Pages. A separately
deployed, stateless broker performs the confidential GitHub App OAuth exchange.
It stores no CMS content, media, role data, audit data, or long-lived browser
credentials.

## Browser-safe configuration

The generated admin configuration may contain only:

- `GITHUB_APP_CLIENT_ID`
- `GITHUB_AUTH_BROKER_URL`
- fixed repository identity: `Iyad-Ayoub/astra-team.github.io`

The broker alone stores the GitHub App client secret. Never place that secret,
the App private key, a PAT, installation token, or workflow token in this
repository, the Pages artifact, or browser configuration.

## Endpoints

### `GET /authorize`

The browser redirects to the broker with:

- `client_id`
- `redirect_uri` — the Pages `/admin/auth/callback/` URL
- `state` — a browser-generated random value
- `code_challenge` and `code_challenge_method=S256`
- `return_to` — an ASTRA admin route generated by the browser

The broker validates the fixed client and allowed Pages callback URL, retains
the transaction only for the OAuth exchange, and redirects to GitHub. The
broker receives the GitHub authorization code; it must not pass that code to
GitHub Pages.

### Callback to Pages

After a successful exchange, the broker redirects to the supplied callback
with only a one-time opaque `ticket` and the original `state`. On failure it
returns a non-sensitive `error` value. It must not place an access token,
refresh token, GitHub code, client secret, or repository credential in the URL.

### `POST /session/exchange`

The browser sends JSON containing `ticket`, `state`, `code_verifier`, and
`redirect_uri`. The broker validates the ticket, state, PKCE verifier, allowed
callback, and transaction expiry. It returns only:

```json
{ "access_token": "short-lived GitHub user token", "expires_at": "ISO-8601 timestamp" }
```

The browser holds this short-lived token in `sessionStorage`, never
`localStorage`, and clears it on logout, expiration, or access failure. It uses
the token only for `GET /user` and fixed-repository access verification in G1.

## Local development

Run a local broker implementation outside this repository and set
`GITHUB_AUTH_BROKER_URL` to its HTTPS-capable development origin. Its allowed
callback list must include the local Pages/Jekyll admin callback URL. The
repository contains no broker implementation, secret, or mock token path.
